# RELEASE v0.11.1 — Patch

**Status:** ready (CI-only fix, no behaviour change)
**Theme:** the `v0.11.0` tag run failed in the Real-browser budget job.

## Release notes

### Fixed
- `make browser-test` asserted an absolute 50 ms on a shared GitHub runner that is ~30× slower than a laptop
  (CI log: `init exec 189 ms, long tasks 56 ms`; slowest click handler 32 ms vs 0.5 ms locally).
- The init measurement subtracted `responseEnd` of `t.js` from the end of init. Chrome had already preloaded the
  script, so `responseEnd` fell before the start marker and inflated the number. It now measures from
  `max(t0, responseEnd)`.
- The budget is **machine-normalised**: a fixed CPU workload calibrates the runner. The limit is 50 ms on the
  reference machine (`REF_CALIB_MS = 35`, the development laptop) and scales up only when the runner measures
  slower. Calibration, budget and measured values are printed in the job log, so a real regression on a normal
  machine still fails.

## Verification
`make browser-test` locally with real Chrome: `init exec 10.4 ms, long tasks 0.0 ms, calib 34.5 ms (ref 35),
budget 50 ms`, slowest click handler 0.5 ms, 3/3 pass. Clean `git ls-files` checkout on Node 22.23.3:
`make check` and `make browser-test` exit 0 (before this change; `browser-test` re-verified after).

## No AC changes
AC0.10.3 keeps its three tests and the same 50 ms criterion; only how a slow machine is accounted for changed.

## Folded in: CI fixes found by the first `v0.10.0` run

The first `v0.10.0` tag failed in CI/Release/Integration/Audit. There is no separate v0.10.1; the fixes ship here.

- `make tracker-test` / `browser-test` ran `node --test test/`. Node 22 (CI) treats a directory as a module path;
  tests are now passed as globs (`test/*.test.mjs`). `make check` verified on Node 22.23.3.
- `cargo audit` flagged RUSTSEC-2023-0071 (`rsa` via `sqlx-mysql`, no patched release): accepted with
  ADR 0051 (`.cargo/audit.toml`, `deny.toml`, CI audit step), guarded by a test that every ignored advisory has
  an Accepted ADR.
- `make test-db` ran every `#[ignore]` test including the ones that need a compose stack or a read-only DB
  user; it now skips those (`make stack-test`, `make ro-user-test`) and uses `--no-fail-fast`.
- Dependabot opened ~20 failing PRs (weekly, majors included) and was removed: dependency updates are manual,
  each behind the full gate; the pending majors are planned as v0.11.0.
- `make release` is the same target as `~/code/veda` (bump, amend into HEAD, push, tag, push tag; only the
  `git add` list differs for Cargo files). Workflow: commit, then `make release VERSION=x.y.z`.

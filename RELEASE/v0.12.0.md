# RELEASE v0.12.0 — Quickstart and tutorials

**Status:** ready — static + binary checks green offline; first-run flow and Docker split need a tag run (user)
**Theme:** *A new user gets from `git clone` to a populated Grafana dashboard in five minutes, and can use their own tools on top of GreptimeDB.*

## Why

Everything worked, but a newcomer had to: copy and edit a config, hash an API key, run `migrate` by hand,
find the right compose command, invent data, and guess which table to query. The release workflow's
"Build and push" also never finished: the arm64 image was built under QEMU emulation (30+ minutes and still
running on every tag).

## Scope

1. **Zero-edit compose.** `docker compose up -d` uses [docker/quickstart.toml](../docker/quickstart.toml)
   (demo site `pk_demo`, API key `demo-api-key`, loud "demo only" header). A one-shot `migrate` service
   (`greprum migrate --wait 90`) creates the tables and flows; `greprum` starts after it succeeded.
   `GREPRUM_CONFIG=./greprum.toml` swaps in a real config.
2. **`greprum migrate --wait SECS`** retries while GreptimeDB starts.
3. **Demo data.** `docker compose --profile demo run --rm seed` (or `make demo` / `make demo-local`) writes
   30 000 deterministic events for site `demo`; [docker/demo-site/](../docker/demo-site/index.html) is a
   one-page shop with the tracker tag.
4. **[tutorials/](../tutorials/README.md)**: quickstart, add the tracker, read the dashboards (all 11
   screenshots), use your own tools on GreptimeDB (tables, columns, SQL, MySQL/HTTP/API, own Grafana),
   going to production.
5. **Docker publish split** (user request: "Build and push always can't finish"): one native job per
   architecture (`ubuntu-latest`, `ubuntu-24.04-arm`) pushes by digest; a `merge` job builds the multi-arch
   tags with `imagetools create`. No QEMU; 30/10-minute job timeouts.
